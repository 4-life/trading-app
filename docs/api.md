# API

Docker service: `api`

FastAPI service, served by Uvicorn (see [README: Tech Stack](../README.md#tech-stack)). Backs the SSR [dashboard](dashboard.md). Every endpoint except `/health` and `/login` requires a login token (see [Authentication](#authentication)).

It exposes system state for reading (papers, positions, PnL, risk status, system health) and accepts only owner control actions — never raw trading instructions from outside.

## Authentication

- `POST /login` `{"password": ...}` → `{"token", "expires_in"}`. The token is valid for 7 days and is signed with a key derived from the app password, so changing the password logs everyone out.
- `POST /logout` (logged in) → `204`: revokes the caller's token in Redis until it would expire — a copy of it stops working too. The dashboard's Log out calls it, then clears the cookie.
- No `/docs`, `/redoc` or `/openapi.json` — the API publishes no map of itself.
- `POST /password` `{"current_password", "new_password"}` (logged in; 8+ characters) → a new `{"token", "expires_in"}`. Stores the new password's scrypt hash in `settings` (`app_password_hash`), which takes over from `APP_PASSWORD` — the env value is ignored from then on. A wrong current password counts as a failed login (rate-limited). Forgot it: delete that row (`DELETE FROM settings WHERE key = 'app_password_hash';`) and `APP_PASSWORD` works again.
- Every other endpoint except `/health` needs `Authorization: Bearer <token>`, otherwise `401`.
- The dashboard server keeps the token in an HTTP-only cookie and forwards the visitor's IP in `X-Forwarded-For`.
- Failed logins are rate-limited per client IP in [Redis](redis.md): after 5 failures in 15 minutes, `429`.

## Endpoints

| Endpoint | Purpose |
|---|---|
| `GET /health` | health check (public) |
| `POST /login` | see above (public) |
| `GET /assets` | the [asset universe](market-data.md#asset-universe), by symbol: `symbol`, `in_use` (a paper needs it — can't be deleted) |
| `POST /assets` | add one, body `{symbol}` (any non-blank symbol, up to 64 characters, no spaces — not checked with the provider); `201`, `409` if already added |
| `DELETE /assets/{symbol}` | delete one and all its market data (candles, trades, order books, funding, open interest, features); `204`, `404` if not added, `409` while a paper needs it |
| `GET /papers` | all papers |
| `POST /papers` | create a paper (a single paper's own `stop_loss_pct` / `price_take_profit_pct`, shares of the entry price, optional — [stop-loss and take-profit](papers.md#stop-loss-and-take-profit); `422` on another kind; `422` for a `leverage` or `add_leverage` above the asset's [max leverage](market-data.md#market-limits); `kind` — `single` / `scanner` / `averaging`, `asset`, `timeframe`, `leverage`, `direction`, `executor`, and for an averaging paper — `long` or `short`, whatever its executor (VWAP too), or `both` where the executor trades both (VWAP, Regime — not Supertrend; each position the direction of its entry) — its [position management](papers.md#averaging-papers) fields, all required except `add_size_usd` and `backtest_start`); always starts in demo. A `single` paper's `asset` must be an added [asset](market-data.md#asset-universe) (`422` otherwise); a `scanner` paper has none and runs `trend` only ([kinds](papers.md#kinds)). Other VWAP papers must be `long` or `both`. Papers carry `kind`, `parent_id` (the scanner that created them) and `prep_status` / `prep_error` ([preparation](papers.md#preparation): a new single paper starts `backfilling`). |
| `PATCH /papers/{id}` | edit: replaces `leverage` and, for an averaging paper, the [position management](papers.md#averaging-papers) fields (`initial_size_usd`, `add_leverage` (at most 5), `add_size_usd`, `take_profit_pct`, `max_drawdown_pct`, `backtest_start`), then re-runs an averaging paper's backtest. `409` for a leverage change while the paper has an open position or an order in flight, or a fractional live leverage; `422` for a missing required field on an averaging paper, or any of them on another kind. |
| `POST /papers/{id}/live` | demo → live. `409` unless `profitability_demo > 0`, leverage is a whole number, the live keys are set, no open position, no order in flight, and the asset's live slot is free. |
| `POST /papers/{id}/sweep` | starts an averaging paper's [settings sweep](papers.md#averaging-papers) in the background, body `{max_leverage, max_margin}`, replacing the paper's previous sweep: its executor, timeframe, add leverage, add size and give-up fixed, every leverage (3–100×) up to `max_leverage` and the asset's [max](market-data.md#market-limits) × initial size × take-profit × mode (hold, intraday, intraday-reopen) over the same period as its backtest (from its `backtest_start`, else its whole stored history), `max_margin` as the budget. Each run's stats are stored as its chunk finishes — the sweep ranks nothing. `202` with the sweep; **`409` while any sweep is running** (one at a time on the server); `422` for a paper it can't sweep (not averaging, no backtest). Nothing about the paper changes. |
| `GET /papers/{id}/sweep` | the paper's sweep (its latest): `status` running / done / failed (`error`) / stopped, `runs_done` of `runs_total`, the period (`start`, `split`, `end`), `max_leverage`, `max_margin`. One marked running while the API isn't running it (cut off by a restart) is turned `failed` ("interrupted"). `404` without one. |
| `POST /papers/{id}/sweep/stop` | stops the paper's running sweep — its worker processes killed, `status` `stopped`, the runs stored so far kept (read them with `GET …/sweep/runs`). `200` with the sweep; `409` when it has none running. |
| `POST /sweeps/batch` | starts a **batch**: body `{paper_ids, max_margin}` — the averaging papers' sweeps (as `POST /papers/{id}/sweep`) one after another in that order, each on `max_margin` (not shared) and up to its asset's [max leverage](market-data.md#market-limits), replacing their previous sweeps and the previous batch. `202` with the batch; `409` while a sweep or a batch runs; `422` for a paper it can't sweep (missing, not averaging, no backtest). While it runs, `POST /papers/{id}/sweep` is `409`; a paper's own stop ends that paper's sweep alone. |
| `GET /sweeps/batch` | the latest batch: `status` running / done / failed (`error`) / stopped, `paper_ids`, `current_paper_id`, `papers_done`, `max_margin`, and `current` — the running paper's sweep (its progress); `null` when none ran. One cut off by a restart is turned `failed` ("interrupted"). |
| `POST /sweeps/batch/stop` | stops the running batch — its running paper's sweep too (`stopped`, the runs so far kept). `409` when none runs. |
| `GET /sweeps/running` | the sweep running on the server, any paper's (one at a time) — same shape as `GET /papers/{id}/sweep`; `null` when none. Interrupted ones are turned `failed` first. |
| `GET /papers/{id}/sweep/runs?sort=total_usd&order=desc&limit=5` | the sweep's runs stored so far (while it runs, the finished ones), sorted by any stat — `total_usd` (closed + open), `closed_pnl_usd`, `open_unrealized_usd`, `train_pnl_usd`, `test_pnl_usd`, `positions`, `won`, `give_ups`, `liquidations`, `most_margin_usd`, `cash_drawdown_usd`, `leverage`, `initial_size_usd`, `take_profit_pct` — or `safest_total`: the fewest give-ups (liquidations counted in), then the best `total_usd`; `most_won_total`: the most winning positions, then the best `total_usd` (both their own order, `order` ignored); `order` asc / desc; `limit` 1–1000; `compound` false / true — the runs on a fixed budget or compounding (`compound_margin`). Each run: its settings (leverage, add leverage, initial / add size, take-profit, intraday, compound), those stats and `drained_at` — the date its cash fell under the initial size and it stopped trading (null: never). Drained runs always come last, whatever the sort, then the **tight** ones — on a fixed budget, their most margin left under 20% of the sweep's max margin unused (`MIN_HEADROOM`: live slippage and fees would have finished them); `robust_only=true` leaves both out. `404` without a sweep. |
| `GET /papers/{id}/sweep/exit-runs?sort=return_pct&order=desc&limit=5` | a **single** paper's sweep runs stored so far ([stop-loss and take-profit](papers.md#stop-loss-and-take-profit)): its `leverage`, `stop_loss_pct`, `take_profit_pct` (null: none) and stats — `return_pct` (compounded at that leverage, % of the margin), `max_drawdown_pct`, `train_return_pct`, `test_return_pct`, `trades`, `won`, `stops`, `take_profits`, `liquidations` — sorted by any of them (nulls last). A single paper's `POST …/sweep` needs no `max_margin`. `404` without a sweep. |
| `POST /papers/{id}/disable` | disable (by owner). `409` while the paper has an open position or an order in flight. |
| `POST /papers/{id}/enable` | re-enable in its current mode. `409` if it's live and the asset's live slot is taken. |
| `DELETE /papers/{id}` | delete a disabled paper and its whole history (positions, orders, decisions, equity snapshots, risk events). |
| `GET /papers/{id}/chart?limit=500` | one paper's [strategy chart](dashboard.md#strategy-chart): the latest `limit` candles at its timeframe (the forming one last), its positions in that window or still open — with every fill (partial closes too), PnL (unrealized at the last close), SL / TP — and every swing (`HH` / `LL` / `HL` / `LH`, pivot and confirmation candle) from the closed candles, the confirmed [liquidity swing zones](swings.md#liquidity-swings) (`liquidity_zones`), the [trend bands](regime-strategy-engine.md#trend-bands) per closed candle (`bands`: state, active band, value edge, break signal), for a Supertrend paper its [Supertrend](supertrend-strategy-engine.md#chart) per closed candle (`supertrend`: line, trend, Buy / Sell; empty for the others), plus every temporary [backtest](vwap-strategy-engine.md#backtest) trade (`backtest`, with fills — the whole backtest, for the summary; the chart draws those on its candles). `limit` 50–6000. `404` for an unknown paper. |
| `GET /papers/{id}/candles?before=<ISO time>&limit=2000` | the strategy chart's older history, loaded as it scrolls back: the `limit` candles before `before` (oldest first) with the first window's overlays on them — VWAP + EMA 9 and their BUY / SELL (`vwap`), the trend bands (`bands`), a Supertrend paper's Supertrend (`supertrend`), the swings and confirmed liquidity zones pivoting in the chunk (`swings`, `liquidity_zones`) — computed from `CALC_BARS` (5,000) candles before it and 200 after it, so they match the full history's. `limit` 50–5000; empty once the stored history ends. `404` for an unknown paper. |
| `GET /portfolio?mode=demo\|live` | the mode's cards (equity, available balance, open positions, exposure, total / unrealized / realized PnL) and its open and closed positions (latest 200 closed). Live reads the Hyperliquid account; without the live keys it returns `live_data: false` ("no live data"). |
| `GET /decisions?mode=&asset=&page=&page_size=` | the trading log, newest first, paginated (`page_size` ≤ 500). |
| `GET /system-health` | watchdog results and kill-switch state; `deploying` — a [deploy](watchdog.md#deploys) running or just finished (its alerts' quiet window): failing checks are its restarts |
| `GET /settings` · `PUT /settings` | integration keys, encrypted with `SETTINGS_ENCRYPTION_KEY`; returned masked (last 4 characters). `PUT` changes only the given keys; an empty string removes one. `503` if the encryption key isn't set. |
| `GET` / `POST /auto-open` | read/set live auto-trading (Redis key `live:auto_trading`, missing = off — so off after every start). While off, executors place nothing for live papers (no entries, no exits — each signal logged as `rejected_by_risk`, "live auto-trading off") and live positions aren't liquidated by the app. Demo ignores it. |
| `POST /reset` | demo reset — see [papers: Demo Reset](papers.md#demo-reset). Never touches live. |
| `POST /positions/{id}/close` | manual close: queues an exit request (reason `manual_close`) in the order queue, like any executor exit; once it's placed the paper is **disabled** (by owner, "position closed manually" — enable it to trade again); returns `decision_id`. `404` if the position isn't open, `409` if the paper already has an order in flight. Doesn't change the auto-trading switch. |
| `POST /positions/{id}/closed-on-exchange` | `{close_price}` — records a live position already closed on Hyperliquid as closed at that price (reason `closed_on_exchange`); no order is sent. Realized PnL = price move − entry fee − estimated taker exit fee; live profitability is recomputed. `204`; `404` if the position isn't open, `400` if it's a demo position, `409` if the paper has an order in flight. |
